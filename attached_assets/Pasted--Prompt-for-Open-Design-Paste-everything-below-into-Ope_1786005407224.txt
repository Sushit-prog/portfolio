# Prompt for Open Design

Paste everything below into Open Design as your initial build prompt.

---

You are an expert full-stack web developer and portfolio designer. Build a personal portfolio website for **Sushit**, an AI Engineer (fresher-level, completed an AI/ML Engineering internship at iNeuBytes) based in West Bengal, India, currently pursuing a B.Tech in Electronics and Communication Engineering at Guru Nanak Institute of Technology.

## Positioning

Sushit's professional identity is broader than "infra/evals engineer" — he wants to be read as an **AI Engineer** who ships both reliability tooling *and* agentic systems. His portfolio thesis is **"LLM reliability and safety tooling"**, spanning two pillars:

- **Pillar A — Infra / Eval / Reliability**: gateways, circuit breakers, drift monitors, eval harnesses, security frameworks
- **Pillar B — Agentic Systems**: multi-agent research copilots, SOP-compiled agent runtimes, hackathon platforms

The site's job is to get him AI Engineering internships and entry-level AI Engineering / AI Infrastructure roles. It should read as serious, technical, and open-source-grade — not demo-ware.

## Visual Design System

Use a **terminal / hacker aesthetic**, locked to this exact palette:

- Background: `#0A0F08` (near-black, slight green tint)
- Primary accent / bright green: `#8AFF57`
- Secondary accent / lime: `#CAFF3C`

Design direction:
- Monospace fonts throughout (e.g. JetBrains Mono, Fira Code, or IBM Plex Mono)
- Terminal-window motifs: blinking cursor, command-line prompts (`$ whoami`, `$ cat projects.json`), scanline/CRT-glow touches used sparingly (tasteful, not gimmicky)
- Dark, high-contrast, code-editor feel — think a well-designed dev tool, not a neon rave
- Subtle animation on load (typewriter text, fade-ins) but nothing that slows down usability
- Fully responsive, fast-loading, accessible contrast ratios despite the dark palette

**3. Featured Projects** (grid or terminal-list layout, filterable by pillar if feasible)

**5. Skills**

**6. Contact**

## Technical Requirements

- Clean, semantic HTML/component structure (React preferred if the tool supports it)
- Fast initial load — terminal aesthetic should not mean heavy animation libraries
- Mobile-first responsive layout (terminal aesthetic often breaks on small screens — test this carefully)
- SEO basics: meta title/description, OpenGraph tags for link previews
- Easy to update project list later — treat the project data as a structured list/array, not hardcoded markup, so new projects can be added quickly

## Tone

Confident, technical, understated. Let the projects do the talking — avoid generic "passionate about AI" copy. Every section should read like it was written by someone who ships production-grade tooling, not a student portfolio template.
